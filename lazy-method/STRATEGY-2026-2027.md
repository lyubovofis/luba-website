# SEO + GEO Strategy 2026-2027

**Last updated:** 2026-05-23
**Status:** Living document — update as Google + LLM behavior shifts
**Scope:** Canonical, niche-agnostic framework. Drop into any project. Replace `{niche}`, `{primary_keyword}`, `{city}`, `{expert_name}`, `{credentials}` with the per-site values.

> **North star** — every page must win attention in **two parallel surfaces** that increasingly overlap:
> 1. **Classic Google SERPs** — organic + local pack (where relevant).
> 2. **AI surfaces** — Google AI Overviews, ChatGPT browse, Perplexity, Bing Copilot, Claude search.
>
> We optimize the same page for both. Every page must be **citation-ready**: short paragraphs, declarative answers, schema-rich, fast-loading.

## 1. What changed in 2025–2026

These are the eight shifts that drive every other decision in this document. If a page does not respond to all eight, it is a 2024-era page.

| # | Shift | What it means | Our response |
|---|-------|---------------|--------------|
| 1 | **Calibrated word-count targets, completeness > length** | Google ranks topic completeness, not raw word count. Padding hurts both rankings and AI extraction. | Set a **target** per page type (see niche-profile). Hit the target only when the topic genuinely demands it. Cut ruthlessly otherwise. |
| 2 | **Multi-tier KW strategy + read-aloud test, persona modifiers** | Keyword stuffing is dead. KW density tools mislead. The test is: does it sound natural read aloud? | 4-tier model (Primary / Secondary / Supporting / Persona). Density target 1.5–2.5% primary, but the read-aloud test always wins. |
| 3 | **AI citations driven by third-party mentions across surfaces** | LLMs cite brands that other reputable sites mention, not just brands that publish a lot. | Active PR + citation building: industry directories, niche communities, Reddit, local news, partner sites. Track in DataForSEO `ai_optimization_*`. |
| 4 | **Share of Voice in AI (Overviews + ChatGPT + Perplexity)** | New visibility KPI replaces "ranking #1". Track presence across AI surfaces, not just SERP position. | Monitor monthly: brand mentions in AI Overviews, ChatGPT cited count, Perplexity citations. Set OKRs around AI SoV, not just classic rankings. |
| 5 | **E-E-A-T on every page (Dec 2025 update)** | Google extended E-E-A-T from YMYL to **all competitive queries**. | Author bio with credentials + photo on every indexable page. Real first-party photos. Year founded. License/cert. Outbound citations to authority. |
| 6 | **Standalone paragraphs (LLM extracts individually)** | LLMs extract paragraphs, not full pages. Each paragraph must make sense without its neighbors. | "Lead with the answer" in first 100 words. No "as mentioned above" / "see below" / context-dependent prose. Each paragraph is a self-contained unit. |
| 7 | **Question-phrased H2/H3 + FAQPage schema + speakable** | AI Overviews and voice search pull from question-phrased headings + structured FAQ. | All H2/H3 phrased as the queries users actually ask. FAQPage schema on every page. Speakable schema targeting direct-answer block + FAQ answers. |
| 8 | **Niche specificity > broad volume** | Long-tail wins. 50 queries × 100 vol beats 1 query × 5,000 vol, because long-tail converts. | Programmatic depth: persona-driven copy, neighborhood/sub-vertical specificity, modifier expansion (cost / near me / emergency / best / cheap / 24/7 / how-to). |

## 2. Old vs. new approach

| Aspect | 2022-2024 approach | 2026-2027 approach |
|--------|-------------------|--------------------|
| **Word count** | "3,000+ words wins" | Calibrated target per page type; cut padding |
| **Keyword strategy** | One primary KW, density 1-3% | 4-tier (Primary / Secondary / Supporting / Persona) + read-aloud test |
| **Audience** | Search intent only | Persona + intent + journey stage |
| **Headings** | SEO-friendly H2/H3 | Question-phrased H2/H3 matching PAA |
| **E-E-A-T** | YMYL only | All competitive queries (Dec 2025) |
| **Structured data** | Article + LocalBusiness | Article + LocalBusiness + FAQPage + Speakable + Breadcrumbs + Service/Offer + Author (Person) |
| **KPI #1** | Rank #1 in Google | Cited across AI surfaces + rank in classic SERP |
| **Backlinks** | DR / DA chasing | Citation density across reputable third-party surfaces |
| **Content cadence** | Volume-first | Depth-first; one fully-shipped page > five thin pages |
| **Refresh strategy** | One-and-done | `dateModified` refresh + 100-word additions every 6 months |
| **AI crawlers** | Block or ignore | Explicitly allow GPTBot / ClaudeBot / PerplexityBot / Google-Extended in robots.txt + `llms.txt` |

## 3. The 4-tier keyword model

For every indexable page we define exactly four tiers of keywords:

```
Primary KW       — 1     — title, H1, URL, first 100 words, hero img alt
Secondary KWs    — 3–5   — H2/H3 headings, intro of each section
Supporting KWs   — 8–15  — body, FAQ, schema, image alts
Persona modifiers — 2–4  — phrasing variations matching audience
```

### Density guidance

- **Primary KW:** 1.5–2.5% target (checker floor is 0.5% — below that the keyword is underused; above 2.5% is stuffing). Never higher.
- **Secondary KWs:** 0.8–1.2% each.
- **Supporting KWs:** appear once or twice, contextually only.
- **Persona modifiers:** sprinkle through body where they sound natural.

**Override rule:** the read-aloud test wins. If a passage sounds stuffed when read aloud, it is stuffed — regardless of what density tools say.

### Cannibalization rule

**One SERP cluster = one page maximum.** If two keyword clusters have ≥60% URL overlap on Google SERP, merge them into the same page. Use DataForSEO to verify SERP similarity before assigning.

### Example structure (replace with your niche)

|------|------------------------|------------------|
| Primary | `{primary_keyword}` | `<title>`, `<h1>`, URL slug, first sentence, og:title, hero img alt |
| Secondary | `emergency {primary_keyword}` | H2 "Emergency Service" + intro |
| Secondary | `same-day {primary_keyword}` | H2 "Same-Day Response" + intro |

## 4. The 5 persona archetypes (universal)

These archetypes work for any niche. Adapt the trigger queries and copy notes to your industry — the underlying behavioral pattern stays the same.

| # | Persona | Universal pattern | How to adapt to your niche |
|---|---------|------------------|----------------------------|
| 1 | **Stressed user — emergency** | Acute problem, urgent. Time-sensitive. Searches in panic, often after-hours. | Replace with: homeowner with broken HVAC, parent with sick child needing clinic, business owner with crashed server. Copy: 24/7 availability, dispatch time, reassurance, "we answer when you call". |
| 2 | **Stressed user — broken thing** | Specific item failure. Less urgent than #1 but still pain-driven. Wants price range + safety. | Replace with: broken appliance, leaking pipe, error code on device, failing component. Copy: price range, safety warning, why DIY is dangerous/risky, when to call a pro. |
| 3 | **Planner — researching replacement / new purchase** | Daytime browsing. Comparing options. Wants depth, brand comparison, ROI, financing. | Replace with: home buyer, software evaluator, equipment shopper. Copy: buying guide depth, brand vs brand comparison, ROI / TCO / financing, social proof. |
| 4 | **Cost-checker** | Pre-decision. Wants pricing tables, ranges with explanations, no-surprise pledge. | Replace with: any user researching cost before commitment. Copy: structured price ranges, "what affects the price" section, no-surprise / transparent pricing pledge. |
| 5 | **Decision-maker (B2B / commercial / volume)** | Business hours. Volume needs. Wants contracts, invoicing, SLA, multi-location. | Replace with: property manager, IT procurement, multi-site operator, agency buyer. Copy: volume rates, multi-property / multi-seat / multi-location service, invoicing, SLA, dedicated rep. |

**Rule:** Each indexable page must address **at least 2 personas** explicitly in body or FAQ.

### How to pick personas per page

- **Emergency / urgent service page** → Personas 1, 2, 4.
- **Cost / pricing page** → Personas 4, 3, 5.
- **Buying guide / comparison** → Personas 3, 4.
- **B2B / enterprise page** → Personas 5, 4.
- **Local landing page** → Personas 1 or 2 + 4.
- **How-to / troubleshooting** → Personas 1 or 2 + 3.

## 5. GEO / AI Overviews — 10-point checklist (per page)

Tick **all 10** before publishing:

- [ ] **Direct answer in first 100 words** — declarative sentence answering the primary query verbatim. LLM extraction target.
- [ ] **Standalone paragraphs** — each paragraph readable in isolation. No "as mentioned above" / "see below". LLMs extract paragraphs, not pages.
- [ ] **Question-phrased H2/H3** — headings phrased as the questions users actually ask (match PAA). Not internal jargon.
- [ ] **TL;DR / Key Takeaways block** at top — bulleted, scannable. 3–7 bullets max.
- [ ] **FAQ section** with FAQPage schema — 3–6 questions matching `People Also Ask`.
- [ ] **Comparison tables** where applicable — markdown-style tables get extracted well by LLMs.
- [ ] **Specific numbers** — "1-year warranty", "from $X", "average Y-minute response" beat "fast" and "affordable". Concrete numerics are highly citable.
- [ ] **Citable expert quote** — named expert with credentials, on the topic. Replace with `{expert_name}`, `{credentials}`.
- [ ] **`speakable` schema** targeting the direct-answer block + FAQ answers.
- [ ] **Last-updated date visible** + `dateModified` in schema.

### Why each point matters (one-liner each)

1. **Direct answer first** — AI Overviews extract the first declarative sentence after the H1.
2. **Standalone paragraphs** — LLMs index passages, not pages. A paragraph that needs context to make sense will not be cited.
3. **Question-phrased H2** — AI matches user query to heading. Headings phrased as questions get matched more often.
4. **TL;DR** — voice assistants and AI Overviews prefer scannable summaries.
5. **FAQ + schema** — FAQPage schema directly powers AI Overview FAQ extractions.
6. **Comparison tables** — LLMs parse tables structurally. A 5-row comparison table is highly citable.
7. **Specific numbers** — numerics are quotable. "Fast" is not.
8. **Expert quote** — adds attribution. Citable.
9. **Speakable** — explicit signal for voice + assistant extraction.
10. **dateModified visible + schema** — freshness signal. LLMs deprioritize content with no visible recency.

## 6. E-E-A-T — 10-signal checklist (per page)

Per Google's December 2025 update, E-E-A-T applies to **all competitive queries**, not just YMYL. Every indexable page needs:

| # | Signal | Where to put it | Example |
|---|--------|-----------------|---------|
| 1 | **Author bio** with photo + credentials | Bottom of every page (use `AuthorBio` component) | `{expert_name}`, `{credentials}`, photo, bio paragraph |
| 2 | **Real first-party photos** | Used contextually in body, not just hero | Install photos, team photos, equipment photos — not stock |
| 3 | **Customer quotes** with attribution | Trust section + scattered pull-quotes | First name + last initial + city/role |
| 4 | **Year founded** | Footer + about box on every page | "Since {year}" or "{N}+ years in business" |
| 5 | **License / cert / insurance** | Footer + contact page | License number, association membership, insurance carrier |
| 6 | **Warranty / guarantee** | Pricing, hero, FAQ | "X-year warranty on all work" |
| 7 | **Reviews count + score** | Hero badge + footer widget | "4.9 / 472 reviews" |
| 8 | **Local / niche proof** — geo or sub-vertical specifics | Body paragraphs of landing pages | "Forest Hill garage repair" / "SaaS billing integration" — concrete, not generic |
| 9 | **Editorial standards** statement | `/about/` page or privacy footer | How content is researched, who reviews, who approves |
| 10 | **Outbound citations to authorities** | Body, in-line | Industry association, standards body, gov source, peer-reviewed reference |

### Editorial standards — what to include

The editorial standards page (or block in About) should answer:

- Who writes our content? (named authors with bios)
- How do we research? (data sources, primary research, expert interviews)
- Who reviews before publish? (named reviewer with credentials)
- How do we handle corrections? (correction policy + last-corrected date)
- What is our funding model? (transparent — clients pay us; affiliate-free or affiliate-disclosed)

## 7. Schema.org requirements per page type

| Page type | Required schemas | Notes |
|-----------|------------------|-------|
| **Homepage** | `Organization` (or `LocalBusiness` if local), `WebSite`, `BreadcrumbList` | `WebSite` with `SearchAction` for sitelinks search box |
| **Local landing** (city/region page) | `LocalBusiness` (areaServed = that city/region), `Service`, `FAQPage`, `BreadcrumbList`, `Speakable` | LocalBusiness with city-narrowed `areaServed` |
| **Service hub** | `Service`, `FAQPage`, `BreadcrumbList`, `Offer`, `Speakable` | One Service per page; multiple Offer if pricing tiers |

| **Blog post** | `Article` (or `BlogPosting`), `Person` (author), `Organization` (publisher), `FAQPage` if has Q&A, `BreadcrumbList`, `Speakable` | `dateModified` + `datePublished` always |
| **Pricing page** | `Service` with multiple `Offer`, `BreadcrumbList` | Each tier = one Offer |
| **Contact page** | `LocalBusiness`, `ContactPage`, `BreadcrumbList` | |
| **Calculator / tool** | `WebApplication` or `SoftwareApplication`, `BreadcrumbList` | |
| **Comparison page** (X vs Y / alternatives) | `Article`, `FAQPage`, `BreadcrumbList`, optionally `ItemList` of compared items | |
| **Job page** | `JobPosting`, `Organization` (hiringOrganization), `BreadcrumbList` | |
| **Event** | `Event`, `Place`, `Offer` (if ticketed), `BreadcrumbList` | |
| **Recipe** | `Recipe`, `NutritionInformation`, `AggregateRating`, `Review` | |
| **HowTo article** | `HowTo` with `HowToStep` array, `Article`, `BreadcrumbList` | Steps must have name + text + image where possible |

**Implementation:** centralize in `src/lib/schema.ts` or equivalent. Each page calls `localBusinessSchema(city)`, `articleSchema(post)`, etc. Don't hand-write JSON-LD per page — that drifts.

**Validation:** every page → Google Rich Results Test before publish.

## 8. Hub-spoke internal linking model
> **Multi-location service business (SAB)?** This generic hub-spoke is 1-dimensional. For a service x location matrix, use the 2-D, 3-axis mesh + volume-gated indexing tier in `LOCAL-SERVICE-MATRIX.md` (extends this section).

```
HOMEPAGE
  ↓
SERVICE HUB A        ←→     SERVICE HUB B            (siblings cross-linked)
  ↓                              ↓
LOCAL/LANDING × N      LOCAL/LANDING × N             (one per city / region / segment)
  ↓                              ↓
DEEP CONTENT (blog / how-to / cost / comparison) clustered under each hub
```

### Rules

1. **Minimum 5 internal links per page** (enforced by lazy-method threshold).
2. **Anchor text variety** — never repeat the same anchor 7 times on one source. Vary primary / secondary / natural-sentence anchors.
3. **Cross-link siblings** — every local/landing page mentions 2–3 nearby siblings ("Also serving nearby {city_B} and {city_C}") with anchor links.
4. **Hub → all spokes** — the hub page links to every spoke. Spokes link back to the hub. Spokes link to 2–3 other spokes (not all — keep it natural).
5. **Blog → hub + spokes** — blog posts link up to their parent hub + sideways to 2–3 relevant spokes.
6. **No weak anchors** — "click here", "read more", "learn more" are flagged by lazy-method's internal-linking checker.
7. **No orphan pages** — every indexable URL must be linked from ≥1 other indexable URL.
8. **Breadcrumb on every non-home page** — `BreadcrumbList` schema + visible breadcrumb.

### Cluster depth ratios (rule of thumb)

- 1 hub : 10–20 spokes : 30–60 deep content pieces.
- If you have fewer spokes than 10, you don't have a hub — you have a normal page.
- If you have more than 60 deep pieces per hub, split the hub.

This framework is built on the following 2026 authoritative sources:

1. **Google "Helpful, reliable, people-first content" guidance** — December 2025 update extending E-E-A-T to all competitive queries.
2. **Google Search Quality Rater Guidelines** — current edition. E-E-A-T expansion, YMYL definitions.
3. **Backlinko "SEO This Year" 2026** — third-party citation signals, niche-persona priority, AI-first KPIs (Share of Voice in AI surfaces).
4. **Ahrefs 2026 best practices** — standalone paragraphs, "lead with the answer", passage indexing.
5. **Semrush 2026 SEO best practices** — author bios, AI extraction patterns, structured content.
6. **Boomy Marketing internal `LAZY-METHOD-CHECKLIST.md`** + 20 checker modules (423 parameters). Companions: `DEPLOY-GATE.md`, `LOCAL-SERVICE-MATRIX.md`, `PERFORMANCE-CHECKLIST.md`, `OFFPAGE-LOCAL-CHECKLIST.md`, `MEASUREMENT-KPI.md`.

### What we intentionally do NOT chase

- Arbitrary word counts unless tied to topic completeness.
- Keyword density tools' "perfect %" — read-aloud test wins.
- Backlink count without context — citations beat raw links in the AI era.
- AI-generated boilerplate paragraphs — filtered by AI Overviews, hurts E-E-A-T.
- Excessive subdomain proliferation — hurts topical authority.
- Schema for the sake of schema — every schema block must reflect actual page content. Empty / fake schema is a Google manual-action risk.

## 10. Implementation rule — design system integration (lazy-method content)

When adding content to satisfy lazy-method checker parameters, follow these rules:

### Integrate, don't duplicate
Before creating any new section, ask: **"Does an existing component already cover this signal?"**

| Signal needed | Use existing component |
|---------------|------------------------|
| Team / E-E-A-T | `<About />` — add `class="about-us"` if not present |
| FAQ entries | Add Q&A to the FAQ data file consumed by `<Faq />` |
| How-we-work steps | `<HowWeWork />` |
| Related links / next steps | Add `class="related"` to an existing internal-link block |
| Trust stats / years experience | `<About />` stats row or hero stats |

### Design tokens — always use, never override

Any genuinely new element (a `<dl>`, a stats grid, a callout box) must use the project's CSS custom properties:

```css
/* Colors */
var(--orange)       /* #ff522f — primary accent */
var(--cream)        /* #fff9f0 — section backgrounds */
var(--navy)         /* #1a2744 — headings / dark surfaces */
var(--text-muted)   /* body text, labels */
var(--text-soft)    /* secondary text */

/* Spacing */
var(--space-2) through var(--space-16)

/* Shape */
var(--radius-md)   /* standard border-radius */

/* Type scale */
var(--fs-xs) var(--fs-sm) var(--fs-base) var(--fs-lg) var(--fs-xl) var(--fs-2xl)
```

And utility classes:
`.container` `.eyebrow` `.section-title` `.section-sub` `.fade-up` `.btn` `.btn-primary` `.btn-lg` `.grad-text`

### Never do this

- Raw `color: #ff4500; font-size: 1.2rem; padding: 20px` inline or in an ad-hoc `<style>` block outside the design system.
- New `<section>` that visually duplicates `<About />`, `<HowWeWork />`, `<Faq />`, or `<ServiceOverlap />`.
- Boilerplate team card or step-by-step list already covered by an existing component.
